# Colorado Ballot Explorer: Build Plan

Reviewed by: Bob Rose, 2026-10-14

Source: docs/prd.md, docs/tech-spec.md, docs/design.md (approved 2026-10-14, see REVIEW.md) · Status: draft · Generated by Claude in place of /anvil-plan

## Overview

Two phases, matching the PRD release scope.

- **Pilot (M1 to M5).** Invited testers start October 16, 2026, for the November 3 general election. That leaves two working days to build, so the plan front-loads data, which is the long pole, and runs data and app work in parallel. Anything not needed by a tester on October 16 waits.
- **Release 1 (M6 to M12).** Public, for the November 2, 2027 coordinated election. These milestones are sketched now so every requirement has a home. They will be re-planned after the pilot, because pilot lessons feed a PRD revision first (PRD Release scope), which will also make the current approval stale.

Commands in backticks are the automated checks each milestone must pass. They are created by the milestone that first needs them.

## Milestones

### M1 Pipeline and statewide data (pilot, October 14 to 15)
Monorepo layout from the spec (`pipeline/`, `sources/`, `verification/`, `app/`, `data/`). JSON Schema for statewide, county and ZIP index files. Compiler with schema, ballot-order, count, ballot-text and retention-link checks, hashes and changelog. ZIP index from Census ZCTAs. Statewide items for the November 3, 2026 election from the Secretary of State's certified list and the Blue Book. Single `counties.json` output with the 1.5 MB size budget check.

Requirements: REQ-01 (index), REQ-02 (non-Colorado table), REQ-05, REQ-06 (retention links), REQ-08, REQ-21, NFR-01 (same files for every visitor), NFR-06, NFR-07. Acceptance: AC-07, AC-11, AC-28, AC-37, AC-41 (data side).

Exit criteria:
- `python -m pytest pipeline` passes, including failing-fixture tests for each check (wrong order, count mismatch, ballot text mismatch, missing retention link, missing hash, over size budget).
- `python -m pipeline.build --election co-2026-11-03 --check` builds `zip-index.json`, `statewide.json`, `counties.json` and `hashes.txt` with no errors.
- A second person spot-checks 10 percent of statewide items against the Blue Book and SoS list, recorded in `verification/statewide.yaml`.

### M2 Boulder and Larimer verified (pilot, October 14 to 15, in parallel with M1 and M3)
AI-assisted extraction of the Boulder and Larimer sample ballots to `sources/co-2026-11-03/08013.yaml` and `08069.yaml`, corrected by a person. Verification records with group counts, certified measure text, and source URLs. Research links in the fixed order, campaign links for both sides where they exist. Confirm whether either ballot has a ranked-choice contest.

Requirements: REQ-05, REQ-06, REQ-07, REQ-08, REQ-20, REQ-21, NFR-06, NFR-07. Acceptance: AC-07, AC-11, AC-27, AC-28.

Exit criteria:
- `python -m pipeline.build --election co-2026-11-03 --check` passes with both counties at `verified_complete`.
- Every other county compiles as statewide items only.
- Each county's verification record names its checker and date, and a second person has spot-checked 10 percent of its items.
- Ranked-choice check recorded: none found, or the pilot fallback from design S5 is added to M3.

### M3 Pilot app (pilot, October 14 to 16)
Vite, Preact and TypeScript app. Resolver (`itemsForZip`, `narrow`). Home, Not in Colorado, Ballot with research banner, coverage labels and ProgressBar, Narrow my ballot, item detail for measures, retentions and candidate contests (checkbox variant), Write out my ballot with print stylesheet, Your data with private session and Clear everything, Privacy and Voting basics pages. Store with IndexedDB and in-memory backends, autosave, PrivacyStrip and the leave-page prompt.

Requirements: REQ-01, REQ-02, REQ-04, REQ-05, REQ-06, REQ-07, REQ-08, REQ-09, REQ-10 (vote-for contests), REQ-11, REQ-12, REQ-13, REQ-14, REQ-15, REQ-16, REQ-17, REQ-20, REQ-21, REQ-23, NFR-06, NFR-09. Acceptance: AC-01 to AC-03, AC-06 to AC-10, AC-12, AC-13, AC-15 to AC-23, AC-27, AC-28, AC-31, AC-39, AC-41, AC-42, AC-46.

Exit criteria:
- `npm --prefix app run test` passes (unit and component).
- `npm --prefix app run e2e` passes the pilot flows on mobile Chromium and WebKit at 360 px.
- Manual walk-through of F1, F2, F3, F4, F6 and F7 on a real phone with Boulder and Larimer ZIPs.

### M4 Pilot privacy, quality and deploy (pilot, October 15 to 16)
Privacy guard (off-origin requests, ZIP, coordinates or note text in any request, identical request lists across counties). Strict headers and CSP. Hand-written service worker for offline. axe-core checks. Lighthouse run for NFR-04, reported but not blocking. Host chosen and deployed with logging off.

Requirements: NFR-01, NFR-02, NFR-03, NFR-04 (measured only), NFR-05 (automated only), NFR-09, REQ-23. Acceptance: AC-32, AC-33, AC-34, AC-35 (report only), AC-36 (automated part), AC-39, AC-40.

Exit criteria:
- `npm --prefix app run e2e -- --grep @privacy` passes on every pilot flow, including AC-40.
- `npm --prefix app run e2e -- --grep @a11y` reports no axe violations.
- `npm --prefix app run e2e -- --grep @offline` passes.
- `npm --prefix app run check:prod -- --url <pilot URL>` confirms headers, no cookies and no third-party requests on the deployed site.
- Host's logging setting is documented on the privacy page and in `docs/hosting.md`.
- Pilot invitations sent on October 16.

### M5 Pilot run (October 16 to November 3)
Moderated sessions with invited testers. Data fixes through the pipeline only, each with a changelog entry. Nightly production checks. Real-device performance measurements against NFR-04. Pilot lessons written up for the PRD revision.

Requirements: REQ-20, REQ-21, NFR-01, NFR-04, NFR-07. Acceptance: AC-35.

Exit criteria:
- `npm --prefix app run check:prod -- --url <pilot URL>` passes nightly through November 3.
- At least five moderated sessions held; Usefulness metric (4 of 5 finish and write out unaided) recorded.
- Every reported data error fixed and listed in `CHANGELOG.md` with item, change and date.
- `docs/pilot-findings.md` written, with proposed PRD changes and measured NFR-04 numbers.

### M6 Release 1 data at full scale (2027)
Data model for the November 2, 2027 coordinated election. Extraction and verification for all 64 counties, starting with the largest. Measure `counties.json` at full size; switch to regional bundles with privacy-page disclosure only if it exceeds the budget.

Requirements: REQ-20, REQ-21, NFR-01, NFR-07. Acceptance: AC-27, AC-37, AC-40.

Exit criteria:
- `python -m pipeline.build --election co-2027-11-02 --check` passes with all 64 counties `verified_complete`.
- Size report for `counties.json` recorded; tech-spec updated first if regional bundles are needed.

### M7 Encrypted save and open file (2027)
C6 export and import with Web Crypto, device key, generated five-word code, save sheet and open flow, persistent storage request.

Requirements: REQ-16, REQ-17, REQ-18, NFR-01. Acceptance: AC-24, AC-25, AC-43, AC-44, AC-45.

Exit criteria:
- `npm --prefix app run test -- portable` passes round-trip, malformed-file, wrong-code and plaintext-scan tests.
- `npm --prefix app run e2e -- --grep @portable` passes same-browser and fresh-context restore.

### M8 Error reporting and changelog page (2027)
Report an error with email and GitHub issue choices and their privacy notes. Changelog rendered as a page.

Requirements: REQ-22, REQ-23. Acceptance: AC-29, AC-30, AC-31.

Exit criteria:
- `npm --prefix app run e2e -- --grep @corrections` passes.
- `python -m pytest pipeline -k changelog` passes.

### M9 Ranked choice (2027)
Ranked contest fields and pipeline checks, ranking functions, RankedList, RcvInstructions, CountingExample, ranked write-out lines. Counting example checked against each jurisdiction's official rules.

Requirements: REQ-10, REQ-12, REQ-13, NFR-05, NFR-06. Acceptance: AC-14, AC-47, AC-48, AC-49, AC-50.

Exit criteria:
- `npm --prefix app run test -- ranking` passes.
- `npm --prefix app run e2e -- --grep @ranked` passes, including axe checks.
- `python -m pytest pipeline -k ranked` passes.

### M10 Precise mode (2027)
Statewide simplified boundaries file, point-in-polygon, Use my location and self-hosted map tiles.

Requirements: REQ-03, NFR-01, NFR-02. Acceptance: AC-04, AC-05.

Exit criteria:
- `npm --prefix app run test -- resolve` passes point-in-polygon fixtures.
- `npm --prefix app run e2e -- --grep @precise` passes with the privacy guard.

### M11 QR transfer (2027)
Deflate, multi-code QR generation and camera reading with vendored libraries.

Requirements: REQ-19, NFR-01. Acceptance: AC-26.

Exit criteria:
- `npm --prefix app run e2e -- --grep @qr` passes with a fake camera stream and no network requests.

### M12 Release 1 hardening and launch (2027)
Reproducible build, manual screen-reader pass, NFR-04 targets enforced, production checks, public launch.

Requirements: NFR-04, NFR-05, NFR-08. Acceptance: AC-35, AC-36, AC-38.

Exit criteria:
- `npm run verify:reproducible` rebuilds in a clean container and matches published hashes.
- `npx lhci autorun` meets the NFR-04 targets on the mobile preset.
- VoiceOver and NVDA passes recorded with no blocking issues.

## Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Two days is not enough for M1 to M4 | High | High | Cut in this order, each needing a PRD update first: statewide legislative and congressional contests outside Boulder and Larimer ZIPs; then guided narrowing polish; then the campaign links row. Never cut the privacy guard, verification records or coverage labels. If still short, slip the pilot start rather than ship unverified data. |
| No host chosen yet (PRD Q7) | High | High | Owner picks a host on October 14 or 15 that supports a headers file, lets logging be turned off, and injects no scripts or analytics. T-20 verifies all three on the deployed site. |
| Sample ballot extraction errors in Boulder or Larimer | Medium | High | Count checks, certified text check, second-person spot check, testers report errors directly during sessions. |
| Statewide district data (ZCTA to district) wrong for some ZIPs | Medium | Medium | Conditional labels on every district-dependent item; narrowing; check 10 known addresses against county sample ballots before invites go out. |
| Pilot lessons change the PRD and stale the approval | Certain | Low | Expected. Revise the PRD after M5, re-approve, then re-plan M6 to M12. |
| `counties.json` over budget with all 64 counties | Medium | Medium | M6 measures first; regional bundles with disclosure as the documented fallback. |
